Slik bruker vi Claude til å lage nettsider

Kort versjon av oppsettet vårt, med skillsene og MCP-ene vi faktisk bruker. Alt her kan du sette opp på en ettermiddag.

Hvordan det henger sammen

Vi jobber nesten alt i Claude Code (terminal eller VS Code). Oppsettet har tre lag, og hvert lag løser sitt eget problem:

CLAUDE.mdÉn fil med reglene deres. Hvem dere er, hvordan dere vil ha ting, hva Claude aldri skal gjøre. Leses ved hver økt.
SkillsOppskrifter Claude henter frem ved behov. En mappe med en SKILL.md som forklarer hvordan en type jobb gjøres.
MCP-erKoblinger til verktøy utenfor: Figma, nettleser, Notion, Google Drive. Gir Claude hender, ikke bare hode.

Skills gir kvalitet. MCP-er gir rekkevidde. CLAUDE.md sørger for at det blir likt hver gang.

Kom i gang

  1. Installer Claude Code

    npm install -g @anthropic-ai/claude-code
# kjør i prosjektmappen din
claude

  2. Lag en CLAUDE.md

    Skriv /init i Claude Code, så lager den et utkast. Fyll på med egne regler etter hvert. Vår viktigste vane: hver gang vi retter på Claude, skrives rettelsen inn i filen samme dag.

    # CLAUDE.md (eksempel)
- Landingssider bygges alltid fra templates/lp-mal/
- Aldri AI-genererte bilder; bruk kundens ekte bilder
- Test skjemaet i nettleseren før du sier at noe er ferdig
- Norsk bokmål, kort og konkret

  3. Legg inn noen skills

    En skill er bare en mappe. Legg den i ~/.claude/skills/ (alle prosjekter) eller .claude/skills/ (ett prosjekt). Claude oppdager dem selv og bruker dem når oppgaven passer.

    git clone https://github.com/Leonxlnx/taste-skill
cp -r taste-skill/skills/* ~/.claude/skills/

    Sjekk README i hvert repo; mappestrukturen varierer litt.

  4. Koble på MCP-er

    # nettleser, så Claude kan åpne og teste sidene selv
claude mcp add playwright npx @playwright/mcp@latest

# Figma (offisiell)
claude mcp add --transport http figma https://mcp.figma.com/mcp

    Skriv /mcp inne i Claude Code for å se status og logge inn. Mange tjenester (Notion, Gmail, Drive, Figma) kan også kobles via Connectors på claude.ai.

MCP-er vi får mest ut av

Playwright

Claude åpner siden i en ekte nettleser, tar skjermbilder, fyller ut skjemaet og ser om det faktisk fungerer på mobil. Den viktigste for nettsider.

Figma

Les et design rett inn i kode, eller send en side tilbake til Figma for justering.

Mobbin

Søk i ekte app- og nettsideskjermer for inspirasjon før vi bygger.

Henter brief, tekster og bilder fra der kunden allerede har dem.

Webflow

Hvis siden skal ligge i Webflow, kan Claude publisere direkte dit.

Lag din første egne skill

En skill er en Markdown-fil med et navn og en beskrivelse øverst. Beskrivelsen er det Claude leser for å avgjøre når skillen skal brukes, så skriv den konkret.

# ~/.claude/skills/landingsside/SKILL.md
---
name: landingsside
description: Bygg en landingsside for en kunde. Bruk når noen
  ber om en LP, kampanjeside eller ny side for en annonse.
---

1. Les kundens nettside og hent logo, farger og ekte bilder.
2. Bygg fra templates/lp-mal/. Ikke lag nytt design.
3. Struktur: hero med ett tilbud, før/etter, anmeldelser, skjema.
4. Test skjemaet og mobilvisning med Playwright.
5. Vis meg skjermbilder før noe publiseres.

Start med én skill for den jobben du gjør oftest. Forbedre den hver gang resultatet ikke blir som du ville.

Det vi har lært

  • Én mal slår mange design. Vi fikk mye bedre resultater da vi sluttet å be om «noe nytt» hver gang og heller lot Claude fylle en mal vi vet konverterer.
  • Skriv reglene ned med en gang. En rettelse du bare sier i chatten, er glemt neste økt. I CLAUDE.md eller en skill blir den permanent.
  • La Claude teste selv. Med Playwright fanger den brukne skjemaer og mobilfeil før du ser dem.
  • Ekte bilder. AI-bilder på en landingsside merkes, og de selger dårligere. Bruk kundens egne.
  • Ikke installer alt. Fem skills du kjenner er bedre enn femti Claude må velge mellom.
